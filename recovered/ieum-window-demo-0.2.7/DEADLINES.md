작업 전 미커밋 변경 없음. 원본 복구 기록 RECOVERY.md와 recovery-notes, 저장소 루트의 기존 설치 파일·분할 파일·해시·설치 스크립트는 유지했습니다. 구현은 복구 하위 폴더에 한정합니다.

대화 메시지와 쪽지 발송 시 정규표현식으로 기한을 찾아 발신자와 수신자 각각의 `deadlines`에 저장합니다. 외부 API, AI 모델, 인터넷 호출을 사용하지 않습니다. 기존 교내 HTTPS/SQLite 서버는 그대로 사용합니다. 시작·종료 시간 필드 없이 날짜와 `dueTime`만 저장합니다. 발신자도 같은 마감 일정을 공유하며, 쪽지에는 본인의 일정 링크가 연결됩니다. 기존 보강/수업 변경/공유 일정/일과표 안내는 별도 일정이 있으므로 중복 추출하지 않습니다.

- ‘오전 중’, ‘점심시간 전까지’: 12:05. 관리자가 저장한 해당 날짜 임시 일과표가 우선이고, 변경한 기본 일과표도 적용합니다. 4교시가 없으면 12:05입니다. 원래 복구본의 미설정 기본 일과표는 변경 일과표로 취급하지 않습니다.
- ‘내일까지’, ‘16일까지’, ‘다음 주 수요일까지’: 16:00. 명시한 시각은 우선합니다. 12시간제 오전/오후, HH:mm, 시·분·반을 지원합니다.
- 상대 날짜는 서버가 저장한 실제 발송 시각의 한국 시간 기준입니다. 예약 쪽지는 예약 발송 시각 기준으로 해석하고 실제 전달 때 등록합니다. 재조회 시각과 클라이언트가 보낸 createdAt은 사용하지 않습니다.
- 다음 주는 월요일 시작, ‘16일’은 발송 월의 16일로 해석합니다. 지나간 날짜를 다음 달로 이동시키지 않습니다. 여러 문장은 문장/줄별로 처리합니다. 한 문장에 여러 업무·기한이 섞인 복잡한 문장은 지원 범위 밖입니다.
- 원본 종류·메시지 ID·캘린더 소유자 ID·추출 순번을 고유 키로 기록합니다. 메시지 저장과 자동 등록은 같은 SQLite 트랜잭션에 포함합니다. 재시도·재동기화·재시작·재조회에서 중복 등록하지 않으며, 사용자가 삭제해도 다시 만들지 않습니다.
- 일과표 변경 시 자동 추출된 점심 마감 시각도 갱신됩니다. 사용자가 일정을 수정하면 일반 개인 마감 일정으로 저장되어 자동 시간 갱신 대상에서 벗어납니다.
- 이전에 저장되어 있던 서버 메시지의 일괄 소급 등록은 하지 않습니다. 새 메시지부터 적용합니다. 브라우저/Windows 체험 데모는 예시 수신 메시지에도 같은 규칙을 적용하며 로컬 저장소로 이력을 유지합니다.

## 실행 및 테스트

Node.js 24 이상에서 `npm install`, `npm test`. Electron 개발 실행은 `IEUM_ROLE=demo`로 지정하고 설치한 Electron 44.7.0에서 이 폴더를 엽니다. package.json의 scripts는 추가했으나 Electron은 런타임 의존성으로 추가하지 않았습니다.

Windows 다운로드 데모는 `release/Ieum-Deadline-Demo-0.2.11-win-x64.zip`입니다. 모두 압축 해제한 뒤 `Ieum-Deadline-Demo.exe` 또는 `START-DEMO.cmd`를 실행합니다. 기존 0.2.7 설치 파일을 덮어쓰지 않는 x64 무설치 데모이며 Node.js/인터넷/교내 서버가 필요 없습니다. 내 캘린더의 ‘메시지 일정 체험’에서 본문과 한국 발송 시각을 입력하면 마감 일정이 보입니다. 같은 창에서 수신 체험을 반복해도 한 번만 등록됩니다. 새 창의 체험은 별도 메시지입니다.

빌드 재현: 공식 Electron 44.7.0의 `electron-v44.7.0-win32-x64.zip`과 같은 릴리스의 `SHASUMS256.txt`를 준비한 뒤 `python3 scripts/build-windows-demo.py <런타임 ZIP> <SHASUMS256.txt>`. 런타임 해시 검증 후 기존 산출물과 분리하여 ZIP을 만들고 해시를 기록합니다. 빌드 입력 다운로드만 외부 통신을 사용하며 일정 추출/데모 실행은 로컬 처리입니다.

배포 ZIP은 서명되지 않았습니다. 이 Linux 환경에서는 실제 Windows 실행과 SmartScreen 동작을 검증할 수 없었습니다. Linux의 브라우저/Electron 검증 및 ZIP의 PE 실행 파일·앱 리소스 확인 결과는 VALIDATION.md에 기록합니다.

## 메신저 메뉴와 오늘 일정 · 0.2.11

본창의 위치와 크기를 유지하면서 오늘 일정 패널을 별도 부착 창으로 왼쪽/오른쪽에 열고 닫습니다. 슬라이딩은 약 220ms이며 본창 이동/크기 변경에 패널이 따라갑니다. 설정은 왼쪽/오른쪽을 선택합니다. 화면 가장자리에서는 패널이 화면 밖으로 벗어나지 않도록 위치를 제한합니다.

주 메뉴는 쪽지함, 대화, 내 캘린더, 교무업무, 학교소식, 바로가기 순서입니다. 교무업무를 누르면 보강 안내, 수업 변경, 일과표를 선택합니다. 조직도 상단의 별도 업무 버튼과 하단의 선택한 사람에게 쪽지/대화 버튼은 제거했습니다. 이름 더블클릭은 수신자가 지정된 쪽지 작성창을 열며, 사람 우클릭의 대화 메뉴는 대화창을 엽니다. 학교 이름을 누르면 조직도로 돌아갑니다. 키보드로 이름 버튼을 실행하면 쪽지 작성창을 엽니다.
